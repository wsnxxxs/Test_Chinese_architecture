# Millford · 微缩铁路小镇

一个用 **Three.js** 写的桌面微缩景观：木框厚底沙盘、闭合环线铁路、穿城而过的小河与桥梁、
成片的模型建筑、树木路灯，以及一列由 1 台蒸汽机车 + 2 节车厢组成、沿轨道连续运行的火车。
打开页面即是全景视角，列车正在运行；默认暖色夕照，可一键切换昼夜。
场景、贴图、建筑全部由代码程序化生成，没有任何外部模型或图片资源。

---

## 快速开始

环境要求：Node.js ≥ 18（在 Node v26.3.1 上验证通过），无需后端。

```bash
npm install          # 安装 three 与 vite（package-lock.json 已锁定）
npm run dev          # 开发服务器，默认 http://localhost:5173
```

生产构建与本地预览：

```bash
npm run build        # 输出到 dist/
npm run preview      # 预览构建产物
```

> 本项目是纯前端工程：`npm run build` 之后 `dist/` 里的静态文件可以直接由任意静态服务器托管。

## 使用说明

| 操作 | 效果 |
| --- | --- |
| 左键拖拽 | 旋转视角（俯仰角被限制在近似等轴测的范围内） |
| 滚轮 | 缩放（正交相机，0.45×–4×） |
| 右键拖拽 | 平移 |
| `暂停 / 运行` 按钮或 `空格` | 暂停时列车与到站计时器同时停止，状态灯变为「已暂停」 |
| `速度` 滑块 | 0.25×–3×，实时影响巡航速度与进站制动 |
| `复位` 按钮或 `R` | 恢复初始机位、列车位置（StopD − 13.5）与 1.00× 速度 |
| `夜晚 / 白天` 按钮或 `N` | 昼夜过渡（约 1 秒渐变），车站、路灯与部分窗格发光 |
| `全景` 按钮或 `V` | 回到俯视全沙盘的初始机位 |

列车每完成一圈经过 Millford 车站时会先减速进站，停靠约 **2 秒** 后继续前行；
底部状态栏会显示「运行中 / 减速进站 / 车站停靠中 / 已暂停」。

## 场景内容

* **沙盘本体**：46 × 37 的木框厚底底座（木纹边框 + 盖板 + 底板 + 铭牌），草地做成带河道下切的
  高度场，河岸有沙滩与湿痕过渡。
* **闭合环线铁路**：一条连续闭合的 Catmull-Rom 环线，配轨枕、钢轨、道砟，两次跨越河流
  （铁路拱桥），并有一处公路平交道口；车站带雨棚站台、站牌与信号机。
* **小镇**：车站大街、村镇路、西街、磨坊巷、南路、东路、河滨步道等道路与街巷，
  以及车站广场、喷泉公园、长椅、木箱、油桶等小品；建筑含旅店、住宅、学校、邮政局、
  工坊、教堂、水塔、谷仓与带水车的磨坊，共 61 个独立摆放的物件、19 盏路灯。
* **植被**：52 棵树 + 34 丛灌木，按建筑轮廓与道路间隙散布。
* **火车**：机车 + 2 节车厢，各自沿轨道弧长独立定位（非刚体），靠独立车钩间距保持间距，
  车头朝向各自所在位置的切线，车轮按滚动距离转动。

```
src/geom.js           PathTrack（弧长参数化闭合曲线）与 StripBuilder（条带几何工具）

src/materials.js     共享材质 + 昼夜主题注册表（自发光材质与点光源统一插值）
src/base.js           沙盘底座、木框、地形高度场与河道、水面
src/roads.js          道路与小径（含路缘、斑马线）
src/railway.js        轨道、铁路桥、站台、平交道口、公路桥
src/buildings.js      各类建筑、摆放解析器（占位网格 + 最短位移解算）
src/props.js          路灯、长椅、喷泉、水车、人行桥、信号牌、树木灌木
src/train.js          机车与车厢模型、TrainController（弧长驱动 + 进站制动 + 停靠计时）

```

### 几个实现要点

* **闭合轨道用弧长驱动**：`PathTrack` 把 Catmull-Rom 曲线预采样成弧长查找表，
  列车位置以「米」为单位查询，速度和停靠点都能按真实距离计算，不受曲线参数疏密影响。
* **三节车厢各自独立**：每节车厢用自己的车钩偏移 `d = controller.d - offset`
  查询轨道位置与切线，弯道上自然散开并各自转向，不会像刚体一样整体平移。
* **摆位解析器**：建筑先按手工坐标落位，再测量真实包围盒，凡与轨道、水面、道路、模型边缘
  或已落位建筑相碰的，就在候选窗口里取「能腾清障碍的最短位移」，因此不会有建筑突然跳到远处。
* **昼夜主题**：一个注册表统一驱动所有自发光材质与点光源（窗格、灯笼玻璃、的信号牌），
  一次 `set(t)` 完成过渡；阴影相机的视锥按当前太阳方向与模型尺寸自动取景，日夜都不会把阴影裁掉。
* **阴影相机自动取景**：`frameShadowCamera()` 用模型八角点在光源基底上的投影求半宽，
  太阳越斜范围越大，避免边缘投影被裁掉。

**未验证（如实说明）**：

* **真实 GPU 上的帧率没有测量过**。浏览器校验跑在 headless Chrome 的软件渲染
  （SwiftShader）下，1600×857 + 2048² 阴影图只有约 1 fps，那是软件光栅化的限制，
  不能代表真实显卡表现。场景规模：约 7.5 万三角形、约 800 次 draw call、858 个网格、
  16 个光源（其中 13 个点光源）。
* 没有移动端/触摸设备实测（窄屏有布局适配，但触摸环视未验证）。
* 没有接入自动化测试框架，验证手段就是上面这几个脚本。
* 停靠期间不播旅客上下车动画（题述未要求）。

## 工具脚本

```
node tools/check-layout.mjs    布局自检：环线、河道、道路、桥接与平交
node tools/check-town.mjs      建筑摆位自检：间距与相互遮挡
node tools/map.mjs             命令行 ASCII 占用图，查看哪里能放东西
node tools/rects.mjs           占用网格上的最大空地矩形，规划建筑用地
node tools/why.mjs <cx> <cz> <w> <d> [ry]
                               查询某个矩形为什么被挡住（哪条规则占的格）
node tools/verify-page.mjs     浏览器交互自检（需要先启动 vite preview 与带
                               --remote-debugging-port=9222 的 Chrome，脚本头部有完整步骤）
```
