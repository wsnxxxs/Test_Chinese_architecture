道路测试覆盖规划图的连通性与正交性，不是人物导航网格或物理碰撞验收。本项目是轨道镜头浏览场景，没有第一人称行走系统。

## 12 项自动测试

1. 建筑数量为 11，包含所需建筑类型，主殿主体占地最大。
2. 所有离开中轴的建筑均有等尺寸、反向旋转的镜像配对。
3. 规划屋顶矩形不重叠，相邻间隔不小于 3 个世界单位。
4. 道路规划图中的所有目的节点均可由入口到达。
5. 所有道路规划线段均正交且非零长度。
6. 体素坐标和旋转均有限，尺寸均为正，颜色字符串合法。
7. 实例数和三角形数不超过预算，材质实例组数量为 5。
8. 体素位置和高度符合预定场地检查范围，最低处不穿过基底。
9. 相同随机种子生成完全一致的场景数据。
10. 更换种子改变表面处理，但不改变建筑布局。
11. 随机数生成器输出保持在 [0,1) 内。
12. 本地构建的 import map 替换逻辑去掉引擎块中的 CDN 地址。

完整执行输出在 `tests.log`。测试刻意把几何生成与 Three.js 解耦，因此无需 GPU 或安装 Three.js 就能运行；这也是它们不能替代浏览器集成测试的原因。

## 目标设备验收步骤

安装依赖后执行 `npm run build -- --offline` 和 `npm run preview`，再用启用硬件加速的浏览器打开预览地址。应确认页面不需要点击“开始”即可看到整座建筑群，检查主殿、双塔、配殿和山门的层级，以及沿不同方向旋转时屋面 / 地面有没有异常穿插。

分别测试三种光影、巡游、复位、标签、建筑拾取、小地图、截图与触屏操作。移动端应检查工具栏没有溢出且入口仍展示完整布局。

保持标签页前台可见，预热约 5 秒，再执行 README 中的 30 秒旋转 benchmark。记录设备、GPU、浏览器版本、实际像素分辨率、画质、主题、平均 FPS 和 P95 帧时；将平均 ≥30 FPS 与较低长帧比例同时作为检查依据。若不达标，切换“流畅优先”或降低分辨率后重新测试，不要将目标值直接写成实测结果。

## 预览图的限制

`geometry-preview.png` 来自项目的同一份长方体位置、尺寸、颜色及旋转数据，经 VTK 离线渲染。该图用于确认总体布局、层叠屋顶、塔楼体量、道路与景观位置。

图中不包括最终 HTML 界面、浏览器 Canvas 匾额、Three.js 主题过渡、拾取或实时帧率。其阴影、曝光与材质和实际浏览器实现不同。它不是应用运行截图，也不是将静态图片冒充可交互场景；正式应用始终由 `src/main.js` 使用 Three.js 渲染。
