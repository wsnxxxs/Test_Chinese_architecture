# 柳溪铁路镇 · Willowbrook Railway

一个以 **Three.js + 原生 JavaScript + Vite** 实现的桌面微缩铁路沙盘。无需后端，也不依赖在线模型、贴图、字体服务或 API。场景模型由代码生成，木纹、草地、墙面、招牌和灯光光晕使用程序化纹理。

> **验证状态**：源码已完成；20 项运动逻辑与平面几何测试、12 个 JavaScript 模块的语法/本地导入路径检查已通过。当前交付环境无法解析 npm 依赖源，安装依赖失败，因此尚未完成 Vite 成功构建和真实浏览器/WebGL 渲染验证。详细记录见 [VALIDATION.md](./VALIDATION.md)。

## 安装与运行

需要 Node.js **20.19 或更高版本**、npm，以及支持 WebGL 2 的浏览器。首次安装依赖需要能够访问 npm 软件源。

```bash
# 在解压后的 willowbrook-railway 目录中执行
npm install
npm run dev
```

打开终端显示的地址，默认是：

```text
http://localhost:5173
```

生产构建与本地预览：

```bash
npm run build
npm run preview
```

预览服务默认地址：

```text
http://localhost:4173
```

构建成功后，将 `dist/` 目录部署至静态 HTTP 服务即可。Vite 的 `base` 已设置为 `./`，用于相对资源路径。不要直接双击源码 `index.html`，也不要用 `file://` 打开构建文件代替 HTTP 服务。

依赖版本在 `package.json` 中固定为 Three.js `0.180.0` 和 Vite `6.3.5`。由于本次依赖安装未成功，交付包不含 `package-lock.json`、`node_modules/` 或已编译的 `dist/`；正常执行 `npm install` 后会生成锁文件。交付的是完整源码项目，而不是已验证的预编译版本。

## 默认场景

页面初始化代码设置为暖色傍晚、完整沙盘的近等距正交视角、列车以 **1×** 速度运行。

展示底座具有木质厚度、边框、脚垫和金属铭牌。草地被真实河槽分成两岸，铁路沿圆角矩形闭合环线铺设，并通过一座绿色桁架桥和一座石拱桥跨河。第三座道路桥连接两岸街道。

柳溪站位于前侧，站前通路接入主街。沿街安排咖啡馆、面包房、花店、书店，后排以住宅与钟楼组织轮廓；河东设置谷仓、菜地、水塔和小屋。屋顶、窗框、烟囱、雨棚、站台边缘、长椅、灯柱、树冠及岸石采用实体模型式几何，而非体素堆叠。

红黑蒸汽机车牵引两节绿白客车。三节车体分别沿轨道行驶，转向架按各自轨道采样点定位，连接杆随相邻车体的位置和角度更新。车轮随实际行驶距离转动，并带有轻量蒸汽效果。

以上描述对应源码中实现的场景内容，最终视觉效果尚待真实浏览器检查。

## 使用方式

| 操作 | 效果 |
| --- | --- |
| 运行 / 暂停按钮；空格键 | 同时暂停或恢复列车位移、车轮转动、蒸汽时间和停站倒计时 |
| 速度滑块 | 调整为 0.25×–2×；不改变每次停站的 2 秒时长 |
| 白天 / 夜晚按钮；`N` 键 | 切换暖阳傍晚与蓝调夜景；夜晚开启站灯、路灯、部分窗户和机车照明 |
| 鼠标拖动 | 旋转沙盘视角 |
| 滚轮 / 触控板缩放 | 放大、缩小，受安全范围约束 |
| 触屏单指拖动、双指缩放 | 旋转与缩放 |
| 复位按钮；`R` 键 | 恢复初始机位、缩放、列车位置、1× 速度、运行状态、白天，以及全部列车计时和停站计数 |
| 右上角说明按钮 | 查看操作说明 |

键盘焦点位于输入控件或按钮、或说明对话框打开时，场景快捷键不接管键盘。暂停列车不会锁死视角或昼夜切换，也不会暂停水面环境动画。页面切至后台时不累计行驶时间，返回后不补跑离开期间的路程。

列车每次到站停留约 **2 个有效运行秒**，然后继续行驶。停站期间按暂停，剩余倒计时保持不变；继续运行后只消耗剩余的停站时间。

## 运动与空间组织

### 共享的轨道几何

`src/route.js` 是轨道、枕木、列车和几何测试共同使用的路径来源。闭合环线由四条直线与四段四分之一圆弧组成，以实际弧长作为参数，没有将整列车作为刚体绕小镇中心旋转。

机车位置使用累计行驶距离 `s`，两节客车分别使用 `s - 2.10`、`s - 4.20`。车体朝向由前后转向架采样点的连线确定；车体位置取该弦的中点。车距已按整个弯道上的车体包络测试调整，而不只检查直线间距。

### 停站状态机

`RailwaySimulation` 以未取模的行驶距离记录下一次车站事件。一次更新中可分别处理“驶向车站”“消耗剩余停站时间”“继续出发”，避免跳过停站或一帧多次误触发。停站时间使用有效运行秒，而不是速度倍率缩放后的时间。

渲染循环限制异常长的单帧时间增量，以降低卡顿后的位移突跳；逻辑测试则单独验证较大时间步和多圈情况下的事件处理。它不是现实铁路运营或动力学仿真。

### 河流、桥梁与净空

河槽边界与跨河判断使用同一组河流函数。铁路道砟在跨河区段断开，轨面连续经过桥面；建筑尺寸与车站站台也从共享布局参数生成。测试检查了两处铁路跨河位置、建筑及檐口的平面铁路净空、车站停车对齐，以及道路位于环线内部的连接规划。

## 性能取向

静态模型按材质和阴影属性合并网格；轨枕、道砟、花丛等重复元素采用实例化。动态车体与轮组内部也分别合批，保留独立运动根节点。几何体和纹理尽量复用。

设备像素比设有上限，窄屏降低阴影贴图分辨率。太阳采用单个方向光阴影；夜景的局部灯光不创建点光源阴影，并配合低成本光晕与地面光斑。代码包含窗口尺寸响应、WebGL 上下文丢失提示以及资源释放逻辑。

这些是已实现的优化措施，**不是经过设备实测的帧率保证**。本次未测量浏览器帧率、显存占用或不同 GPU 的表现。

## 测试

运动逻辑和布局测试不依赖 Three.js 或 Vite，安装 Node.js 后即可运行：

```bash
npm test
npm run check
```

- `npm test`：20 项轨道、车厢间距、车体包络、到站、暂停、速度、复位与布局测试。
- `npm run check`：使用 Node 解析检查 JavaScript 语法，并检查相对模块路径是否存在。**不能替代安装依赖、Vite 构建或浏览器测试。**

开发模式下，或在页面地址后附加 `?debug` 时，提供只用于本地调试的接口：

```js
window.__RAILWAY__.snapshot() // 逻辑状态、列车姿态、机位、渲染统计等
window.__RAILWAY__.reset()
window.__RAILWAY__.setNight(true)
```

此接口不会发送数据到网络。

## 调整沙盘

- 建筑与道路布局：`src/layout.js`。
- 初始车速、起始位置、车距、停站时长、轨道尺寸：`src/route.js`。
- 初始机位、缩放范围、昼夜灯光、阴影质量：`src/world.js`。
- 材质颜色与纹理：`src/materials.js`。

轨道或建筑尺寸发生变化后，应重新运行测试，并在浏览器检查转弯包络、站台净空、树冠、桥梁和完整沙盘取景。自动测试不能替代所有三维视觉与碰撞检查。
