# 卡片模型加载优化

## 改动

- 提前提取和简化原作场景，为此前没有模型包的 54 份作品生成 `.sbox`。加上导入的 9 份，现在全部 63 份卡片都直接读取模型包。
- 模型包只包含卡片原本使用的远景网格，保留原布局、材质、实例、颜色和纹理。中式建筑的裁剪边界沿用原卡片实现。
- 最多同时读取 3 份模型，可见卡片优先于视口外的预加载卡片；新作品的原作提取回退仍逐件处理。
- 使用按 8 字节对齐的二进制缓冲，直接创建 TypedArray 视图，减少解压后的整块数据复制；保存包围球和取景范围，减少加载时重新遍历几何。
- 预览位置量化为 16 位，法线和适用的颜色存为 8 位；位置在解码时恢复 Float32，单个坐标误差不超过对应几何跨度的 `1 / 131070`。预览纹理长边最多 256 像素，以 WebP 保存。完整原作资源不改变。
- 场景提取、体素合并和细节简化的模块仅在回退加载时导入，正常卡片加载不下载这些模块。

54 份生成模型包从未压缩精度与纹理前的 **75.38 MiB** 降至 **40.84 MiB**，减少约 **46%**。导入的九份原始模型包不修改。

## 本机验证

- 在相同本地浏览器、相同排序下，选择 Anthropic 并滚动至卡片，测量操作开始到 Sonnet 5.5 Max 卡片首次显示模型：优化前 **3165 ms**，优化后 **314 ms**。这是一次本机对比，浏览器已有公共模块缓存，不代表所有作品或网络的加载耗时。
- 建筑、铁路、键盘的首批卡片均成功显示，控制台无错误，且没有创建用于重新建模的隐藏 iframe。
- 生成任务成功 54 份，失败 0 份；汇总数据确认 36 份建筑、17 份铁路、10 份键盘都有直接模型入口。
- JavaScript 语法检查与站点汇总构建通过。原作源码、截图、布局和截图对照面板不修改。

## 重新生成

先构建作品和站点，再运行 `npm run bake:previews`。打开终端显示的本地生成页，点击「开始生成」；完成后执行 `node scripts/assemble.mjs`。生成脚本将压缩后的包写入 `site/assets/scenes/`，无需在访问画廊时再执行建模。

修改已有作品模型时用 `npm run bake:previews -- --force`。导入的九份原始包不在强制重生成范围内。`node scripts/compact-previews.mjs` 可压缩此前生成但尚未压缩的第二版模型包；正常生成流程已自动执行这一步。

## 铁路小镇取景修复

铁路卡片以实际沙盘主体计算取景范围：忽略透明度为零的物体、桌面阴影，排除尺寸远大于沙盘的平面桌面。实例粒子池中缩到极小并停在地下的闲置粒子不导出；其余实例保留原位置和颜色。

铁路主体范围包含完整底座，不使用建筑场景针对远山的尺寸筛选。因此 Qwen 的闲置烟雾、Terra 的透明月亮、Astra Pro 的桌面不再影响主体缩放，Astra High 的底座也完整计入取景。

修复后逐行核对了全部 17 份铁路卡片：均已加载并显示完整沙盘，主体占用空间接近，未发现空白或被放大截断的卡片。生成成功 17 份，失败 0 份。

仅重新生成铁路模型可用 `npm run bake:previews -- --force --task=miniature-railway-town`，完成后执行 `node scripts/assemble.mjs`。此规则只用于铁路卡片，完整原作、建筑沙盘和截图界面不修改。

## 收录与手机预览

收录检查现在要求每份作品具有可读取、非空的模型包；第二版提取包还必须完成压缩。超过 3 MiB 的包提示人工核对手机加载，不作为统一性能评分。生成命令支持 `--id=<结果标识>`，结合 `--task` 可只处理新增或更新的单份作品。

手机卡片预览并发从 3 降为 2，像素密度最高为 1，离屏模型缓存目标从 9 降为 6；桌面保留原配置。首次绘制和尺寸调整时，每帧在绘制至少一张卡片后检查 8 ms 时间预算，剩余卡片留到后续帧，减少同一帧集中上传与绘制。单张复杂模型仍可能超出预算，需要结合模型大小和实际手机体验判断。
