## 本轮目标

用户要求优化收录流程：AI 收录已完成作品太慢，且可能一次收录多份；注意可维护性与工程性，不过度防护与测试。随后采纳「主 README 数量与作品目录自动生成」，并要求提交。

## 改动

- 新增 `npm run intake`（`scripts/intake.mjs`）：只构建选中作品（及本机缺 `dist/` 的作品）→ assemble → 自起 vite preview 截图 → 无头生成卡片模型包 → assemble → 刷新 README 目录 → 收录检查；可重复运行，失败步骤汇总后非零退出。
- `bake-previews.mjs` 新增 `--auto`：用 Playwright 无头 Chrome 驱动原生成页，不再需要人工点击。
- `results.mjs` 新增 `resultFilter`：`--id` 支持逗号分隔与 `<task>/<id>` 写法，`capture-results`、`bake-previews`、`check-intake` 共用。
- 新增 `npm run readme`（`scripts/readme.mjs`）：按 manifest、`gallery.json`、`task.json` 重写主 README 中 `catalog:*` 标记内的数量表与各题目录；`check-intake` 发现过期时报错。主 README 其余散落的数量改为不含数字的表述。
- manifest 中 13 条 `model` 改为 README 原有显示名（键盘 GPT 名称去掉连字符、Arena 与日期版本区分等）；该字段只作元数据，站点不读取。Boeing 787 与腾势 Z 的 `task.json` 增加 `promptPending`，用于目录中「提示词待补充」。
- 文档：`docs/intake-workflow.md` 第 3–7 节改写，新增批量收录与多会话分工；README、`docs/ARCHITECTURE.md`、`docs/preview-loading.md`、`HANDOFF.md` 同步。

## 决策

- README 目录行顺序改为 manifest 顺序（原建筑题 5 份新作品置顶、键盘 Arena 两份插在中间），内容与数量不变。
