# ORBIT 65 · 交互式机械键盘产品展示与配置页面

一个原创紧凑配列机械键盘（ORBIT 65）的产品展示页：用 **Three.js** 实时渲染 3D 键盘，用原生 HTML/CSS 承载全部配置操作。无后端，配置保存在浏览器本地。

![技术栈](https://img.shields.io/badge/Three.js-r180-7d9cff) ![Vite](https://img.shields.io/badge/Vite-7-7d9cff)

## 快速开始

```bash
npm install       # 安装依赖（three + vite）
npm run dev       # 启动开发服务器 → http://localhost:5173
npm run build     # 生产构建 → dist/
npm run preview   # 本地预览构建产物 → http://localhost:4173
```

打开页面后无需任何配置：首屏即呈现完整产品名、简介、3D 键盘与主要配置控件。

## 功能

### 产品展示
- **68 键 / 5 行紧凑配列**：完整字母区（A–Z）、数字行、四向方向键，以及不同宽度的空格（6.25u）、回车（2.25u）、Shift（2.25u / 1.75u）、Tab、Caps、Backspace 等，共 7 种键宽。
- **三层结构**：键帽（带锥度、0.1u 缝隙、可读字符）→ 轴体/卫星轴 → 定位板 → 底壳。底壳有厚度、4.5° 输入倾角、内腔隔音棉、前脸铭牌与背部 USB-C 开孔。
- **相机控制**：拖拽旋转、滚轮缩放、按钮或双击画布复位视角；开场自动推近，默认视角完整展示产品。

### 配置（3 × 3 任意组合，实时同步）
- **外壳配色**：星野白 / 深空灰 / 极夜黑（极夜黑搭配橙色阳极定位板）。
- **键帽主题**：复古灰白 / 墨黑透光 / 奶油汽水；Esc、回车、空格与方向键为重点配色键。
- 右侧「配置摘要」与 3D 预览随每次点击同步更新。

### 拆解 / 组装
- 一键在键帽层、定位板层、底壳层之间平滑展开与合拢，展开时显示层级标签并自动重新取景。
- 动画按"指数趋近目标"实现：快速反复点击后始终收敛到最新一次点击的目标位置，三层精确归位。

### 键盘体验模式
- 开启后按下实体键盘 **A–Z 或空格**，对应键帽下压并弹性回弹（阻尼弹簧动画），伴随合成轴体音效（WebAudio，无音频素材）。
- 触屏 / 鼠标直接点击键帽同样触发下压；悬停有抬升反馈。
- 焦点位于输入控件（input / textarea / contenteditable）时完全不拦截键盘输入；体验模式下空格仅用于键帽回弹，不会滚动页面或重复触发按钮。

### 本地保存
- 所有配置自动写入 `localStorage`（键名 `orbit65:showcase:config:v1`），刷新后自动恢复，摘要提示"已从本地恢复"。
- 「保存配置」手动保存并显示时间戳；「恢复默认」**只删除本页自己的配置键**，不影响浏览器中其它数据。

## 实现要点

- **字符渲染**：整套键帽顶面字符绘制进一张 Canvas 图集（9 × 8 格），键帽顶面 UV 指向各自格子；侧面走纯色材质，切换主题只需替换贴图，68 颗键帽共 1 个纹理。
- **拆解动画**：`value += (target − value) × (1 − e^(−5.6·dt))`，与帧率无关、可随时反转，天然解决"快速连点后归位"问题。
- **键程动画**：每键独立阻尼弹簧（刚度 640 / 阻尼 28），按下 0.15u 行程，松开带回弹过冲。
- **取景**：按模型包围盒对相机视锥做投影迭代，求出"完整入画"的距离；拆解/复位沿当前视角方向平滑重新取景。
- **环境光**：`RoomEnvironment` + PMREM 生成环境反射，方向光产生接触阴影，ACES 色调映射。

## 已验证 / 未验证说明

实际执行过 `npm run build`（构建通过）与 `npm run dev`，并在浏览器中完成以下验证：

- 首屏渲染、68 键模型、字符可读性、默认视角（截图确认）；
- 外壳/主题切换 → 预览与摘要同步；图集像素级核对重点键配色无串位；
- 拆解三层展开/合拢（含 8 次快速连点后精确归零与自动取景）；
- 体验模式 A / 空格按住下压、松开回弹归零；键帽点击脉冲回弹；
- 输入控件聚焦时按键不触发键帽、不被页面拦截；空格键 `preventDefault` 生效；
- 刷新恢复配置、恢复默认仅清除本页键（无关 localStorage 键保留）；
- 音效开关、复位视角、toast 反馈。

自动化测试环境中浏览器后台会挂起 `requestAnimationFrame`，动画数值验证通过逐帧步进渲染循环完成；真实前台浏览器中由 rAF 正常驱动。移动端触屏手势（真实设备上的多点触控旋转）未在真机验证。
